# 需求、实现与注意事项总览

本文档整理项目讨论中提出的产品需求、已经实现的功能、关键业务规则和实现方式，供后续开发、测试和维护使用。

这里的“需求提示词”是按语义重写后的工程需求，不是聊天记录的逐字复制。密码、私人课表内容、设备内数据及其他敏感信息不得写入仓库；用户提供的截图只作为视觉参考，截图中的文字不视为额外指令。

## 1. 产品目标

开发一款名为“咕嘎课程表”的本地优先 Android 课程表应用，主要面向小米澎湃 OS 2，同时保持普通 Android 设备的兼容性。

核心目标如下：

- 主界面使用“星期列 × 节次行”的表格，而不是列表。
- 桌面小组件以表格展示从当天开始的未来七天课程。
- 课程表的节次数量、上下课时间、星期列及显示规则由课表数据决定，不能写死为某一所学校的作息。
- 支持每周、单周、双周、起止周及不规则指定周次。
- 支持电脑编辑文件、手机导入，应用内也能快速新建、编辑、复制和粘贴课程。
- 同一星期、同一节次允许保存多门课程，并正确处理轮换课程和冲突课程。
- 支持全局或单节课程的课前提醒，提醒方式可选通知弹窗或持续响铃闹钟。
- 全新安装保持空白，不自动放入演示课表。
- 用户的私人课表不得进入 Git 仓库，交付文件放在仓库外的指定交付目录。

## 2. 需求提示词整理

### 2.1 表格与周视图

- 参考系统课程表的紧凑表格形式，顶部显示周次与日期，左侧显示节次和起止时间。
- 本周不上但以后或以前存在的课程保留在格子中并灰显。
- 左右滑动切换周次，页面必须跟随手指实时移动，松手后只完成吸附动画。
- 不固定显示“上午、下午、晚上”等分段标题；只有 JSON 明确设置 `breakAfter` 时才显示自定义分隔文字。
- 一天有几节课、每节课几点开始和结束，全部由数据配置。
- 可以单独设置某个星期是否显示，也可以自动隐藏整学期完全没课的星期。
- 可以单独设置某个节次行是否显示；隐藏只影响展示，不应破坏已有课程数据。

### 2.2 课程与周数

- 每条上课安排都有课程名称、星期、节次、备注和周数规则。
- 教室不作为强制独立字段，统一允许填写在备注中；旧文件的 `classroom` 仍兼容导入。
- 每条安排可设置开始周、结束周，以及每周、单周或双周。
- 还可以直接指定不规则上课周次，并可额外排除某些周。
- “当前第几周”必须由学期第一周日期和当前日期计算，不能把某次测试时的周次写死在代码中。

### 2.3 同一格多门课程

- 同一星期、同一节次可以保存多门课程。
- 当前周有课时优先显示当前课程；当前周没有课时，灰显最近将要上的课程；未来都没有时，灰显最近已经结束的课程。
- 同一格最多同时展示两门课程：第一门占上半格，第二门占下半格。
- 超过两门时，主界面显示剩余数量，点击格子仍能查看和管理全部课程。
- 两门课程在相同周次发生时间重叠时，保存数据但弹出冲突警告，并在格子右上角显示感叹号。
- 冲突课程仍应同时显示，不能因为冲突而丢弃其中一门。

### 2.4 编辑操作

- 点按空白格新增课程，点按有课的格子选择并编辑其中的课程。
- 支持修改课程名称、备注、周数规则和单节提醒。
- 支持删除课程安排。
- 长按课程复制，长按空白格粘贴到新的星期和节次。
- 当一个格子含有多门课程时，当前长按行为复制排序后的第一门；需要编辑或选择其他课程时先点按格子进入完整课程列表。
- 新建课程表时，从学期名称、第一周日期、总周数和自定义节次开始建立，不依赖模板数据。

### 2.5 文件导入、导出与关联

- 正式交换格式选择结构化 JSON，而不是依赖难以可靠校验的自由文本。
- 应用内提供导入、导出和新建入口。
- Android 文件管理器选择“其他方式打开”JSON 时，可以选择“咕嘎课程表”。
- 导入后的所有布局设置仍可在应用内修改，并在再次导出时完整保留。
- 原始表格文件只用于离线转换和测试；转换后的私人 JSON 与 APK 放在仓库外，不提交 Git。
- JSON 导入必须先完整解析和校验，成功后再一次性替换当前课表，避免半成功状态。

### 2.6 小组件与澎湃 OS

- 桌面小组件从当天开始显示未来七天，而不是固定显示本周周一到周日。
- 小组件与主界面共用节次、星期显示规则和周数计算。
- 小组件同样支持同一格上下显示两门课程。
- 普通 Android AppWidget 可以直接侧载使用；进入小米小部件中心或获得负一屏专用能力，仍需要后续的小米开发者账号、专用规范适配与审核。

### 2.7 提醒

- 可设置提前 `0–180` 分钟提醒。
- 全局策略包括关闭、每节课提醒、每天第一节课提醒。
- 每条课程安排可以继承全局、单独开启或单独关闭。
- 单独开启时可使用自己的提前分钟数和提醒方式。
- 提醒方式包括高优先级弹窗通知和持续响铃闹钟。
- 提醒配置必须写入 JSON，随导入导出迁移。
- 旧 JSON 没有提醒字段时默认关闭，升级应用不能突然产生提醒。

### 2.8 开发与交付约束

- 开发工具按软件自身的通用位置安装；若默认会污染用户家目录，应优先使用 `/opt/<software>` 等共享位置。任何密码或令牌都不得写入项目文件。
- 默认使用无窗口、静音模拟器进行构建、截图、日志和自动化测试，不抢占用户桌面焦点。
- 用户明确连接真机并要求 ADB 调试时，才在真机上覆盖安装和验证。
- 真机覆盖安装前后，应比较应用私有课表文件哈希，确认用户数据未改变。
- 测试结束后关闭模拟器、ADB、Gradle 守护进程，并删除测试文件和临时截图。
- APK 和私人课表的默认交付位置是 `/home/guga/交付产物`；仓库只保留不含个人信息的示例模板。

## 4. 关键业务规则

### 4.1 周次计算

`AcademicTerm.startDate` 表示第一周周一。界面、小组件和提醒都通过同一个学期模型计算日期所属周次。学期外日期不伪造成当前周：小组件仍可显示日期，但课程按学期前或学期后的状态处理。

`WeekPattern` 的判断顺序为：

1. 日期对应周必须位于 `startWeek..endWeek`。
2. 如果存在 `activeWeeks`，以精确周次集合为准。
3. 否则应用 `EVERY_WEEK`、`ODD_WEEKS` 或 `EVEN_WEEKS`。
4. 最后排除 `excludedWeeks`。

### 4.2 同格显示优先级

`SelectSlotDisplays` 对同一格的全部候选课程排序，并最多取两门：

1. 当前选择周正在上的课程；
2. 距离当前周最近、未来会上的课程；
3. 距离当前周最近、过去上过的课程；
4. 在有效范围内没有任何上课周的兜底项。

同级课程使用安排 ID 保证稳定顺序。每个结果重新标记 `isActive`，展示层只根据该状态选择正常颜色或灰色，不重新实现周数计算。

主界面使用两个等高 Compose 子区域；桌面小组件使用一个纵向 `RemoteViews` 容器，并动态加入一到两个等权重课程视图。点击主界面格子时传递完整候选列表，因此第三门及之后的课程仍可编辑。

### 4.3 冲突

两条安排只有在同一天、时间区间重叠，并且至少共享一个实际上课周时才构成冲突。单双周互斥或精确周次完全不相交时不算冲突。

冲突是警告而不是导入失败条件。这样可以保存真实存在的待确认安排，同时通过对话框和感叹号提醒用户处理。

### 4.4 提醒覆盖顺序

- 单节 `reminder.enabled = true`：完全使用单节的分钟数和方式，即使全局关闭也提醒。
- 单节 `reminder.enabled = false`：该安排不提醒。
- 省略单节 `reminder`：继承全局策略。
- “每天第一节课”以当天实际生效课程中最早的开始时间为准；相同最早时间的课程可以各自提醒。
- 已经过提醒时间的事件不会补发；调课、导入、编辑、重启、跨日、系统时间或时区变化后重新排程未来事件。

## 5. 数据格式与持久化

正式文件格式见 [课表 JSON 格式](TIMETABLE_JSON_FORMAT.md)，当前 `formatVersion` 为 `1`。

顶层快照包括：

- `term`：学期名称、第一周日期和总周数；
- `periods`：全部节次、起止时间、可见状态和可选分隔文字；
- `visibleDays` 与 `hideEmptyDays`：星期显示策略；
- `reminderSettings`：全局提醒策略；
- `courses`：课程及其多条上课安排。

导入文档先映射到纯领域模型并验证不变量，再通过 `TimetableRepository.replace` 一次性写入应用私有文件。生产环境默认状态与预览示例严格分开，因此首次安装没有演示课程。

## 6. 分层与实现方式

项目采用高内聚、低耦合的分层结构：

- `domain/model`：不依赖 Android 的实体和值对象，负责自身不变量。
- `domain/usecase`：周数、显示选择、冲突、布局更新和提醒事件等纯业务计算。
- `domain/repository`：数据访问和导入导出契约。
- `data/importexport`：JSON 文档模型、兼容字段、解析、校验和导出映射。
- `data/local`：应用私有文件持久化。
- `presentation`：Compose 页面、状态、对话框和手势事件。
- `widget`：`AppWidgetProvider`、更新器及 `RemoteViews` 表格渲染。
- `reminder`：系统闹钟调度、通知、响铃服务和系统事件恢复。
- `di`：生产依赖的唯一装配入口。

主要数据流均保持单向：

```text
用户操作或文件
    -> ViewModel / Importer
    -> 纯领域用例
    -> TimetableRepository.replace
    -> StateFlow 新快照
    -> 主界面、小组件和提醒统一刷新
```

这种设计保证主界面、小组件和提醒不会各自实现一套周数规则，也便于使用 JVM 测试直接覆盖复杂边界。

## 7. Android 实现细节

- 最低 Android 8.0（API 26），目标 Android 16（API 36）。
- 主界面使用 Kotlin、Jetpack Compose 和 Material 3。
- 小组件使用 `AppWidgetProvider + RemoteViews`，避免依赖主进程中的 Compose 页面。
- 文件关联通过 Android `VIEW` 和 `SEND` Intent 接收 JSON。
- 通知权限使用 `POST_NOTIFICATIONS`。
- 准点提醒使用 `AlarmManager`；有精确闹钟权限时，弹窗使用精确空闲闹钟，响铃模式使用 `setAlarmClock`，否则降级为系统允许的非精确提醒。
- 响铃使用 `mediaPlayback` 前台服务循环播放系统闹钟声音，用户可通过通知或闹钟页面关闭。
- 全屏闹钟界面受 Android 和厂商系统的全屏通知权限限制；不能全屏时仍保留高优先级通知和响铃服务。
- 开机、日期、时间、时区和精确闹钟授权变化时重新计算提醒。

## 8. 测试与验收方式

常规检查命令：

```bash
./gradlew testDebugUnitTest assembleDebug lintDebug
ANDROID_SERIAL=emulator-5554 ./gradlew connectedDebugAndroidTest
```

测试策略：

- JVM 测试覆盖周数、同格选择顺序、冲突、导入导出、编辑、布局更新和提醒计算。
- Compose 仪器测试覆盖周页面、跟手切换、编辑入口、提醒表单及上下半格尺寸。
- 小组件测试会实际展开 `RemoteViews`，确认一个格子能够加入两门课程。
- 无窗口模拟器用于安装、截图、UI 层级、Logcat 和定时提醒测试，并使用 `-no-audio` 防止响铃打扰。
- 真机测试使用明确序列号，覆盖安装前先备份或计算私有课表哈希，安装后再次比较；不为测试主动修改用户课程或触发真机响铃。
- 每轮结束执行 `git diff --check`、隐私关键字扫描，并清理模拟器、ADB、Gradle 和临时文件。

## 9. 隐私与仓库规则

- 不提交用户提供的 `.xls`、转换后的私人 JSON、真机数据、截图缓存或 APK。
- 仓库中的 `samples/timetable-template.json` 只能包含虚构示例。
- 交付目录和应用私有目录不是源码的一部分，不得通过宽泛的 `git add` 意外纳入。
- 日志和测试输出避免打印完整课表内容；验证数据完整性优先使用文件大小、课程数量或 SHA-256。
- 不把密码、SSH 私钥、令牌、账号信息或设备授权信息写入文档、脚本和提交历史。

## 10. 尚未完成或需要外部条件的事项

- 小米负一屏和小米小部件中心的正式专用接入、上架与审核，需要小米开发者账号和对应平台资料。
- 尚未实现导入前预览、与当前课表合并、撤销历史及多课表切换；目前导入采用完整覆盖。
- 当前持久化使用应用私有 JSON 文件；数据规模扩大或需要复杂查询时，可保持仓库契约并迁移到 Room。
- 深色模式、不同小组件尺寸、省电限制、重启恢复和各澎湃 OS 版本仍应持续做真机回归。
- 发布版本仍需配置正式签名、版本发布流程和应用商店合规材料。

## 11. 后续开发原则

1. 先把新规则写成 `domain` 用例及 JVM 测试，再接入 Compose、小组件或提醒层。
2. 主界面、小组件和提醒必须共享领域计算结果，不能复制周次判断。
3. 新增 JSON 字段要提供安全默认值，并验证旧文件兼容性和导出回写。
4. 涉及用户数据的迁移或覆盖安装必须先做可恢复备份或哈希核验。
5. 新功能完成后更新本文档、格式文档和 README 的当前进度。
6. 任何需要账号登录、厂商审核或真实响铃的步骤都应明确留给用户确认。
